{# The git chip (web-server-guide § The site): this clone's branch state, and the verbs that move it. Lives in the fixed header just before the user pill — git is state about *your clone*, not about the page in the pane, so it belongs on the identity side of `.app-who`'s gap. Same
chassis as Actions, the message chip and the user pill: one menu idiom in the header, not four. Two ways in, one partial: · every block response re-sends it `hx-swap-oob` (like `_crumbs.html`), so the fixed header tracks the pane — one `git status` per navigation, no polling; · `GET /git` renders it plain, for the refreshes below. **This element swaps its CONTENTS, never itself** (`hx-swap="innerHTML"`, and the body lives in `_git_menu.html`) — the same shape the message chip settled on, and now for the same reason: with `outerHTML` every refresh replaced the
, which reset `open`, so a menu that re-read itself *on being opened* would shut a few milliseconds later. Keeping the element also keeps the `.term-offline` class site.js paints on it, and lets the poll trigger below live on the chip itself rather than on a separate span (there used to be one, because an oob `outerHTML` swap on every navigation would have restarted an `every` timer placed here). The oob swap is `innerHTML` for the same reason; every state class the chip wears therefore rides on the inside. Three triggers, no overlap: · `euler:git-changed from:body` — the shell moved the clone. The git commands run in the TERMINAL, which is not a navigation, so `solver/core/osc.py` says so over OSC 5379 and `site.js` turns it into this event (the vault's auto-unlock fires it too, to fill in a worktree the first paint could not scan); · `toggle[this.open] throttle:1s` — opening the panel. The push above can be missed: it rides the terminal's WebSocket, so a disconnected or hidden terminal silently drops it, and an external push moves `origin/master` with nothing local to notice. Opening the menu is the one moment a person is *asking* where their clone stands, and it is exactly when the answer must not be the one the last navigation happened to read. The filter is what keeps it to opening — a bare `toggle` fires on close too, spending a read on a panel nobody is looking at any more. htmx calls the filter with the element as `this` (`r.call(elt, evt)`), so `this.open` reads the state the event just produced. `throttle:1s` because the trigger is a pointer away from being held down: it fires the first open and drops the rest of the second; · `every 600s` — the slow poll, so an external push shows without the user reloading or running a git command. `/git` reads with `fetch=True`, so this is the one that goes to the remote on its own. `git` (a solver.web.site.gitstate.GitState) is the switch, and defaults to None in render._context — so the auth tier's pages, and any tier that cannot read a clone, render the inert chip instead of failing. #} {% if git %}
